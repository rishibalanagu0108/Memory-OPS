1 · Background

What problem is Memory-ops solving?

An agent needs useful continuity—preferences, facts, goals, constraints, and past events—but “save text and vector-search it later” is unsafe. It can leak one tenant’s data to another, return obsolete facts, resurrect forgotten content, or let probabilistic output silently become authoritative.

Beginner mental model: a bank ledger, not a notebook. A notebook lets you overwrite a sentence. A ledger records who wrote what, under which scope and policy, when it became true, which version is current, and whether it was later corrected or revoked. Search indexes are merely finding aids; the ledger remains the authority.

The four architectural laws

Authority

PostgreSQL is canonical

Logical memories, immutable versions, lifecycle state, evidence, idempotency receipts, and outbox events live in tenant-isolated PostgreSQL. Keyword/vector indexes never become truth.

Trust

Deny before touching data

The API authenticates and authorizes tenant/workspace access first. PostgreSQL row-level security repeats tenant isolation as defense in depth. Missing identity or policy fails closed.

Lifecycle

Correction preserves history; forgetting revokes now

A correction appends a version instead of rewriting history. Forgetting changes canonical lifecycle state synchronously, so retrieval stops before the slower physical purge completes.

Evidence

Capabilities earn promotion

Each milestone starts with datasets and thresholds, then runs deterministic tests and a protected holdout. A feature can exist in code yet remain disabled when its declared promotion gate fails.

What has been built, in order

M0

Secure foundation

FastAPI, OpenAPI, typed identities/scopes, deny-by-default authorization, PostgreSQL row-level security, prohibited-secret rejection, idempotent writes, a transactional outbox, retryable workers, and content-free audit telemetry.

M1

Explicit canonical memory

Users or agents can explicitly remember, inspect, and list scoped memory. The data model separates a stable logical memory from immutable versions and evidence. Python and TypeScript SDKs expose the main explicit-memory calls.

M2

Time, correction, conflict, and forgetting

Valid-time and recorded-time queries, linked correction versions, deterministic admission decisions, expiration, immediate revocation, seven-target purge receipts, tombstones, and a deletion-aware restore drill.

M3

Governed retrieval and context

Exact, filtered, PostgreSQL full-text, and local vector retrieval; canonical rehydration; purpose/access/lifecycle filtering; critical-constraint priority; token budgets; abstention; degraded warnings; and evaluation-gated rank fusion.

M4

Next: automatic extraction

Not implemented. The active task is only to define category-specific datasets, safety floors, calibration, reviewer agreement, and promotion thresholds. Extraction must begin in shadow mode with zero canonical writes.

2 · Intuition

Follow one memory end to end.

Suppose an authorized travel assistant explicitly stores: “Rishik prefers a window seat on flights.” The request belongs to tenant A, workspace Travel, subject Rishik, purpose travel, semantic type preference.

1

The request proves its authority

The bearer token resolves to a principal. Machine policy checks memory:write, tenant equality, and the workspace grant. The URL’s tenant is never trusted merely because the caller supplied it. A mismatched tenant stops here.

2

Admission blocks dangerous content

The statement is checked for compromise-enabling secrets such as private keys, bearer tokens, API keys, or payment authentication codes. The checker rejects without echoing the secret.

3

One transaction records everything required for an honest acknowledgement

The service reserves the idempotency key, creates the logical memory, appends version 1, moves the current pointer to that version, records evidence, emits an outbox event, and completes the receipt. If any part fails, the transaction rolls back.

user_memories
  id: mem-123
  tenant/workspace/subject: A / Travel / Rishik
  semantic_type: preference
  lifecycle: active
  current_version_id: v1

user_memory_versions
  v1: "Rishik prefers a window seat on flights."
  purpose: travel
  origin: explicit
  policy_version: local-test-token-v1

outbox_events
  user_memory.version.created(mem-123, v1)
4

A worker builds a disposable derivative

The outbox event can be claimed safely by a worker. If sensitivity policy allows it, the current version receives a versioned local hash-ngram embedding. The embedding records its provider, model, model version, index generation, and canonical version. Retrying does not create a second logical artifact.

5

A later question searches, then distrusts its own search result

For “What seat should I choose?”, context assembly tries keyword retrieval first. If no candidates appear, it uses the local vector fallback and drops low-confidence matches. Crucially, every candidate is rehydrated from canonical storage and rechecked for current version, purpose, valid time, retention, access scope, and lifecycle.

Why rehydrate? An index can be stale. It might still contain v1 after a correction or forget. Returning the index’s copied text would leak obsolete data; returning only after canonical revalidation makes the stale index harmless.
6

Context assembly obeys the budget and favors constraints

Critical constraints are selected before ordinary facts and preferences. If critical constraints alone exceed the caller’s token budget, the service abstains instead of silently dropping safety-critical information. Otherwise it returns domain-labelled items, provenance, warnings, used tokens, and whether the result is partial.

7

A correction adds v2; it does not edit v1

If Rishik explicitly corrects the preference to “aisle seat,” the service appends v2, links it to v1 with supersedes_version_id, and atomically moves the logical memory’s current pointer. Historical valid-time queries can still explain what was believed earlier. Today, this correction behavior exists at the service layer but is not exposed as a public HTTP route.

8

Forget is immediate; physical purge is durable

A forget operation changes lifecycle to revoked and creates a tombstone before acknowledgement, so every governed read stops returning the memory immediately. A worker then records purge completion for keyword, vector, graph, summary, cache, evidence, and canonical targets. Canonical content is deleted last.

3 · Code

How the implementation realizes the model.

A. HTTP boundary and authorization

src/memory_ops/api/__init__.py constructs FastAPI and installs memory/context routes. In src/memory_ops/api/user_memory.py:143, every route is tenant/workspace-shaped. The remember route authorizes before invoking domain logic (:153–178); inspect and forget repeat that pattern. src/memory_ops/api/security.py parses the bearer credential, while src/memory_ops/security/__init__.py performs fail-closed policy checks.

# Conceptual order in remember_memory
authorize_request(request, ResourceScope(tenant_id, workspace_id), "memory:write")
result = UserMemoryService(database, policy_version).remember(...)
return memory_id, version_id, operation_id, operation_status

B. Tenant isolation exists twice

TenantDatabase.transaction() sets the restricted runtime role and a transaction-local tenant identifier. Migrations enable and force PostgreSQL row-level security. This means a missed application filter should still not expose another tenant’s rows.

SET LOCAL ROLE memory_ops_runtime
set_config('memory_ops.tenant_id', tenant_id, true)

RLS policy:
tenant_id = current_setting('memory_ops.tenant_id')::uuid

C. Atomic write = memory + receipt + future work

UserMemoryService.remember() rejects prohibited content, serializes a stable request body, and calls IdempotentWriter.execute() (src/memory_ops/user_memory/service.py:85–96). The writer hashes operation plus body, reserves the key, runs the mutation, inserts every outbox event, and completes the receipt in the same database transaction (src/memory_ops/persistence/writes.py:50–133).

Transactional outbox, in plain language The service never has to choose between “saved the memory but forgot to notify the worker” and “notified the worker about a memory that never committed.” Both records commit together; asynchronous processing can safely happen later.

D. Canonical model separates identity from history

E. Retrieval filters before ranking

RetrievalService implements exact, filtered, keyword, vector, and gated hybrid methods. The shared predicate in src/memory_ops/retrieval/__init__.py:228–243 requires workspace, subject, compatible agent, active lifecycle, current version, matching purpose, valid time, retention, and access scope. Vector rows must additionally match the canonical version, index generation, provider, model, and model version.

F. Context assembly revalidates after ranking

UserContextService.build() uses keyword first and a confidence-gated local vector fallback (src/memory_ops/context/__init__.py:61–109). assemble() hydrates every candidate through current_version(), repeats governance checks, prioritizes constraints, applies the token budget, and reports abstention or warnings (:111–213).

G. Forgetting is a two-speed operation

LifecycleService._revoke() synchronously changes lifecycle and creates a deletion tombstone (src/memory_ops/lifecycle/__init__.py:127–166). PurgeService then works through seven destinations and refuses canonical deletion until the other destinations have completed. This gives immediate privacy behavior plus verifiable physical cleanup.

H. Evaluation can refuse a technically working feature

M3’s protected holdout passed all quality and hard-safety metrics. RRF reached 1.0 NDCG, MRR, and recall with zero safety failures, but its isolated P95 overhead ratio was 248.45× the best simpler baseline against a maximum of 2×. Therefore release_enabled is false, and RetrievalService.hybrid() raises HybridNotPromoted.

Interpret that metric carefully. RRF’s absolute measured P95 was only 0.084 ms. The ratio is huge because the benchmark intentionally excludes database retrieval latency and compares against a roughly 0.00034 ms in-process baseline. The correct conclusion is “the declared comparison gate did not pass,” not “production retrieval is slow.”

Where work resumes

M4-01 will define evaluation artifacts only: category-specific extraction data, safety floors, calibration, reviewer agreement, and promotion rules. The non-negotiable behavior is that automatic extraction begins in shadow mode and performs zero canonical writes. Before that work proceeds, the approved task scope needs to include the shared contract validator used by its mandatory verification command.
